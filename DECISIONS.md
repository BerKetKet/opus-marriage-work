# Architectural & Porting Decisions (`DECISIONS.md`)

Every decision taken during this session is logged below with its rationale and empirical evidence.

## D1. Canonical Plain Text & UTF-16 Locator Mapping
- **Decision**: Define each spine's canonical plain text $T_s$ directly from the engine's ordered blocks and visual words in `build_document_text_layer`, stripping synthetic hyphens (`is_synthetic_hyphen == true`), joining split fragments of the same logical word across line breaks with `""` (0 code units), separating distinct words within a block with `" "` (1 UTF-16 code unit), and separating blocks within a spine with `"\n"` (1 UTF-16 code unit). Images and `<hr/>` emit zero text and use a zero-length anchor `Locator(s, curOffset)`.
- **Reason & Evidence**:
  1. Guarantees 100% 1-to-1 slice identity (`utf16_slice(T_s, w.start, w.end) == w.text`) across all `321` pages and `40,644` words checked in Gate P0b (`0` violations).
  2. Guarantees 100% reflow invariance: tested on `kindle_exam_v3.epub` between `exam3_normal` (`45 px / pitch 68`, 82 pages) and `exam3_small` (`34 px / pitch 51`, 54 pages), producing **16/16 byte-for-byte identical canonical spine texts**.
  3. Avoids mismatch between `FakeReaderEngine`'s `EpubExtractor` regex stripper and `kindle_render`'s CSS/DOM block builder (`epub.py`). Old `FakeReaderEngine` saved offsets are invalidated as permitted by D1.

## D2. Deliberately Missing Fonts (`NotoSansCJK-Regular.otf`, `NotoColorEmoji.ttf`) & Debian System Font Shadowing
- **Decision**: Prevent `Config.resolve_font_path` in reference export (`tools/export_reference.py`) and in the Rust engine from falling back to `/usr/share/fonts/truetype/noto/NotoColorEmoji.ttf` when `NotoColorEmoji.ttf` is absent from `kindle_render/fonts/`. Degrade missing CJK/Emoji fonts to `Bookerly-Regular.ttf` and report pages requiring those fonts (`exam1` pages 50–51, `exam2` page 42) as `NOT RUN: font not supplied` in parity comparisons, while still exporting local reference hashes for determinism checks.
- **Reason & Evidence**:
  - `NotoSansCJK-Regular.otf` and `NotoColorEmoji.ttf` were deliberately omitted from `engine_bundle.zip` (Section 2).
  - On the Debian Bookworm sandbox VM, `/usr/share/fonts/truetype/noto/NotoColorEmoji.ttf` happens to exist, but it is a **CBDT/CBLC bitmap-only font** (whereas the repo's omitted `NotoColorEmoji.ttf` was a scalable COLR/CPAL outline font). Passing Debian's bitmap `NotoColorEmoji.ttf` to `FT_Set_Char_Size(f, size26, 0, 72, 72)` in `raster.py:310` raises `RuntimeError: FreeType FT_Set_Char_Size failed with error code 23` (`FT_Err_Invalid_Pixel_Size`).
  - Treating both `NotoSansCJK-Regular.otf` and `NotoColorEmoji.ttf` as missing causes `Family.special_face` (`fonts.py:637`) to fall back cleanly to `Bookerly-Regular.ttf` with zero crashes across all 314 corpus pages, and preserves **100% pixel identity** with `tools/golden/*.json` on all non-CJK/Emoji pages of `exam1` (`69/69`), `exam2` (`63/63`), and `tables_images` (`44/44`).

## D3. Local Python v1.11.0 Oracle Establishment (Gate P0)
- **Decision**: Use local deterministic references generated by running `kindle_render` v1.11.0 twice in this sandbox (`environment_fingerprint = 0a54d71bb5a5988b99f67f4281f2ff9d339c91c8324fc6496a50d77ebf952e3d`) as the primary parity oracle, while also recording exact comparisons against `tools/golden/*.json`.
- **Reason & Evidence**:
  - `tools/golden/exam3_normal.json` and `exam3_small.json` were recorded at `engine_version = "1.10.1"`, prior to the `v1.10.2` `_skia_bilerp_rgb` cover scaling update (`page.py:24-27`), so page 1 differs from the `v1.10.1` golden while pages `2..82` (`81/81`) and `2..54` (`53/53`) match 100%.
  - `tools/golden/exam1.json` and `exam2.json` were recorded with `NotoSansCJK-Regular.otf` and `NotoColorEmoji.ttf` present, affecting `exam1` page 51 and `exam2` page 42.
  - Double-rendering all 5 available corpora in the sandbox confirmed `314/314` (`100%`) determinism for both layout SHA-256 and pixel SHA-256.

## D4. Scrubber Commit & `pageAtProgress(current: Int)`
- **Decision**: Add `fun pageAtProgress(current: Int): Page = pageAt(Locator(0, current))` to `ReaderEngine`, override it in both `NativeReaderEngine` and `FakeReaderEngine` to resolve cumulative UTF-16 character counts across spines, and update `ReaderViewModel.onScrubberCommit` to call `engine.pageAtProgress(clamped)`.
- **Reason & Evidence**:
  - `ReaderViewModel.kt:178` previously called `engine.pageAt(Locator(0, clamped))`, which failed whenever the user scrubbed into spine $\ge 1$ because `clamped` is a cumulative book-wide character offset (`0 .. totalLocations`), not an offset within spine 0.

## D5. Page Model Wire Format v1 & Replay Double
- **Decision**: Use the tab-separated (`\t`), newline-terminated (`\n`) Wire Format v1 defined in `ENGINE_CONTRACT.md` Section 4 across JNI (`kr-jni` $\leftrightarrow$ `PageModelCodec`), and bundle multi-geometry Python-exported replay fixtures (`valid_book`, `minimal_book`, `reflow_book`) under `engine/src/test/resources/replay/` for `ReplayNativeBridge`.
- **Reason & Evidence**:
  - Requires zero third-party JSON dependencies in `:engine`, parses in $<1\text{ ms}$ on JVM, and allows `ReaderEngineContract` tests to run identically against `FakeReaderEngine` and `NativeReaderEngine(ReplayNativeBridge)` without a compiled `.so`.

## D6. Calibrated Geometry Resolution (`KindleGeometry`)
- **Decision**: Extend `ReaderSettings` and `BookInfo` additively with defaulted parameters at the end of their constructor lists (`kindleGeometryIndex`, `marginHorizontalPx`, `boldnessLevel`, `justify`, `hyphenate`, and `isCalibrated`, `missingFontCount`). Map default `ReaderSettings(fontSizeSp = 16f, lineSpacingMultiplier = 1.3f)` to calibrated preset Index 1 (`size26 = 2688` / `42 px`, `pitch = 57 px`, `x0 = 79`, `right = 1001`).
- **Reason & Evidence**:
  - At Android density `2.625` (`420 dpi`), `16.0 sp * 2.625 = 42.0 px` (`size26 = 2688`), which is the exact body size of `exam2` and `probe`. Preserves 100% backward source/binary compatibility with all existing callers and tests (Rule R4).

## D9. `lxml` Dependency in `kr-parity` Docker Image
- **Decision**: Install `lxml` in `kr-parity` image.
- **Reason & Evidence**: `kindle_render/epub.py:203` parses EPUB XML files using `BeautifulSoup(..., "xml")`. Without `lxml`, BeautifulSoup raises `bs4.exceptions.FeatureNotFound: Couldn't find a tree builder with the features you requested: xml`.

## D10. Static Bundling of FreeType 2.12.1 and HarfBuzz 6.0.0 in Android cdylib
- **Decision**: Compile static `libfreetype.a` (2.12.1) and `libharfbuzz.a` (6.0.0) with Android NDK r30 Clang for `arm64-v8a` and statically link them along with NDK `libc++_static.a` and `libc++abi.a` into `libkindle_render_jni.so` via `kr-jni/build.rs`.
- **Reason & Evidence**: `readelf -d libkindle_render_jni.so` verifies `DT_NEEDED` includes only `libdl.so`, `libm.so`, `libc.so`. The binary is self-contained with zero external dependencies, eliminating any risk of `UnsatisfiedLinkError` on Android for companion libraries and locking FreeType 2.12.1 and HarfBuzz 6.0.0 bit-for-bit on device.

## D13. Real EPUB Ingestion via Deep Link & Internal Storage
- **Decision**: Wire `opus://open?path=...` in `AndroidManifest.xml`, `MainActivity.kt`, and `DebugFixtureController.kt` to import real EPUB files via `EpubImporter`, saving the unpacked book into the application's internal files directory (`/data/user/0/app.opusreader/files/epubs/`), and passing the validated absolute path to `ReaderViewModel.loadBook(book.id)`.

## D15: Bounded LRU Cache, Bitmap Reuse Pool, and Allocation Purge (Stage E1)
- **Settled**: `NativeReaderEngine` uses `PageBitmapLruCache` (maxCount=5, maxBytes=60MB, maxPoolSize=3) backed by `BoundedLruCache`. Evicted bitmaps are placed in `reusablePool` for reuse by future page renders rather than reallocated. Reusable `canvas_buf: Vec<f32>` and `rgb_buf: Vec<u8>` in Rust `Rasterizer` eliminate 38 MB alloc/free churn per page. `bridge.trimMemory()` invokes Android Bionic `mallopt(M_PURGE, 0)`.
- **Reason & Evidence**: Previously, memory exploded to 567+ MB native heap because `scheduleNeighborPrefetch` used `putIfAbsent` (bypassing `removeEldestEntry`), and every page render allocated a fresh 6.2-10.1 MB direct `ByteBuffer` and `Bitmap`. Furthermore, the 7 ms vs 175-390 ms latency discrepancy was traced to cache-hit vs cache-miss: drawing an already rendered cached bitmap takes 0.12 ms on the phone, while full Rust page rasterization takes 156.31 ms p50 off the UI thread. With prefetch and bitmap reuse, cache hit rate is 90%+ during continuous reading and memory remains strictly bounded.
