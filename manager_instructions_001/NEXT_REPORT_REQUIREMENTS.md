# What report 002 must contain

The zip is `opus_marriage_work_worker_report_002.zip`, built by `scripts/make_report.py --n 002 --staging deliverables/report_002 --forbid <device serial>`. Maximum about 25 MB; if larger, split into `_002a.zip`, `_002b.zip` and say so.

Required contents (paths inside the zip):
1. `REPORT.md` (one page first): per task T0-T5 a verdict (PASS / FAIL / NOT RUN: reason), the three or four key facts, what is still broken (ranked). Then details. No claim without evidence file names.
2. `screenshots/` with every image listed in `screenshots/DESCRIPTIONS.tsv` (file name TAB what it shows). No duplicates, nothing black or blank unless that is the subject.
3. `specs/kindle_survey/` complete as far as you got (T4), with `INDEX.md`.
4. `test_reports/`: the unit-test result XML files (fresh run, `--rerun-tasks`) and a text file with the counts you computed from them (tests, failures, errors, skipped). Instrumented-test XML if the device ran them.
5. `patches/`: `git_state.txt` (generated by the script) plus `opus-reader.diff` and `render.engine.diff` since the last commit I saw (`git diff <previous report's last commit>..HEAD`, text only).
6. `docs/`: updated `TODO_ISSUES.md` (every owner-reported issue: screenshot, the owner's words, cleaned wording, status), `DECISIONS.md` (new decisions only), `BLOCKERS.md` if any.
7. A final list "what I could not verify and why".

Never include: fonts, hyphenation tables, `.so`, `.a`, APKs, zip archives, build folders, the device serial, personal account details from the Kindle app.
